# Thevenin / Cirq 1.0 Readiness Checklist

Last reconciled 2026-07-12. The three release goals:

1. **Thevenin** is practically compatible with ngspice within numerical
   tolerances on real-world circuits.
2. **Cirq** is a feature-complete source language replacement for SPICE —
   anything an engineer would write in SPICE, they can write natively in
   Cirq.
3. **Cirq's SPICE importer** accepts any arbitrary SPICE netlist a user
   might throw at it without bespoke pre-massaging.

## Status snapshot

- `thevenin` 0.3.0, `thevenin-types` 0.3.0, everything else 0.1.x.
- 1479 workspace tests passing, 0 skipped; harness at 107/107, `ignore.toml`
  empty. Clippy / fmt clean; wasm build green.
- **Simulator core is `Expr`-free + Netlist stamping path removed** (2026-06-29):
  all ~25 device-model loaders consume a neutral numeric `ModelParams` boundary;
  `mna_ir` assembles every device from the IR natively (`ModelParams::from_ir` +
  `ir_numeric_params`, no `convert_model`/`extra_params`); independent V/I sources
  read DC + waveform straight from `cirq_ir::SourceSpec`/`cirq_ir::Waveform` (no
  `convert_source_spec`); and the legacy `assemble_mna(&Netlist)` stamping path
  (~4 kLOC) is deleted. The whole MNA assembly + transient/AC path is `Expr`-free.
  Remaining `thevenin_types::Expr` lives only in the harness-only `output.rs`
  formatter and the SPICE import boundary (see Cross-cutting).
- **Goal C (SPICE importer) is complete** as of 2026-06-17 — every C-section
  item is checked or explicitly scoped out (`.modeldir`/`.step` fall under the
  HSPICE/PSPICE dialect punt). Highlights of the final pass: `if(c,t,e)` brace
  function, two-node `v(n1,n2)` in `.print`/`.meas`, end-to-end `.model` brace
  param resolution, the `wrdata` control command, 3-terminal VDMOS `M` parsing,
  and a focused real-world import corpus (`cirq-spice-import/tests/corpus.rs`).
- Stage 4 (Netlist → Cirq IR retirement) **complete**: only public
  simulator surface is `thevenin::circuit::simulate(&Circuit)` and the
  per-analysis variants. `.control` interpreter runs on Circuit — analysis
  commands parse straight to `cirq_ir::Analysis`, no `thevenin_types::Analysis`
  intermediate. `--legacy` flag gone. See
  `archive/migration/cirq-adoption-plan.md` for the historical arc.

## Out of scope for 1.0

Explicit non-goals so we don't accidentally chase them:

- Dynamic library code-model loading (`cm` shared objects, runtime XSPICE
  plug-ins). Compiled-in XSPICE models via the registry stay.
- Interactive shell features: command history, `cd`/`pwd`, `shell`,
  gnuplot integration, persistent `set`/`unset` state.
- **HSPICE / PSPICE dialect support.** Real netlists from these tools will
  fail to import; users translate or run them through their own tool's
  preprocessor first. Anything beyond what stock ngspice itself parses is
  post-1.0.
- Co-simulation (Verilog-A, TCL, external solvers).

## Goal A — Thevenin practical ngspice compatibility

### A1. Device models

- [x] Resistor, capacitor, inductor, mutual coupling (K)
- [x] Independent sources (V, I) with DC, AC, all 6 waveforms
- [x] Dependent sources (E, F, G, H)
- [x] Behavioral sources (B) with V=/I= expression modes
- [x] Diode
- [x] BJT level 1 (Gummel-Poon)
- [x] BJT level 4 (VBIC)
- [x] MOSFET levels 1, 2, 3, 6
- [x] BSIM3v3 (level 49)
- [x] BSIM4 (level 14 / 54)
- [x] BSIM3SOI FD, PD, DD (levels 55/56/57)
- [x] JFET
- [x] MESFET, HFET, generic MESA family
- [x] LTRA, TXL, CPL, T (ideal lossless) transmission lines
- [x] XSPICE code models (A element, compiled-in via registry)
- [x] **Switches (S, W)** — voltage- and current-controlled. Hysteretic
  conductance via `thevenin/src/switch.rs`; stamped through the NR loop
  with latched state persisting across iterations/timesteps. Supported
  models: `SW`/`VSWITCH` and `CSW`/`ISWITCH` (`Vt`/`It`, `Vh`/`Ih`,
  `Ron`, `Roff`).
- [x] **URC (uniform RC transmission line)** — implemented as a SPICE
  importer macro expansion. `Uname n1 n2 ngnd model L=len [N=lumps]` +
  `.model NAME URC (...)` expands into N stages of R/C (or R/C/D when
  `ISPERL > 0`) at import time, matching ngspice's `urcsetup.c`. The
  simulator never sees a URC element. See
  [`cirq-spice-import/src/lib.rs`](../cirq-spice-import/src/lib.rs)
  `expand_urc`.
- [x] **BSIM1** — ported from ngspice (`b1ld.c`/`b1eval.c`/`b1temp.c`). Implemented in [thevenin/src/bsim1.rs](../thevenin/src/bsim1.rs). DC + NR companion path with full process-parameter table including `_L`/`_W` size binning; AC charge/noise out of scope for the 1.0 cut.
- [x] **BSIM2** — ngspice LEVEL=5 port. Implemented in
  [thevenin/src/bsim2.rs](../thevenin/src/bsim2.rs); ports `b2eval.c` (DC
  drain-current and derivatives, threshold via vfb/k1/k2, mobility
  Ua/Ub/U1, subthreshold n0/nb/nd, impact-ionisation Ai/Bi, cubic-spline
  blend between strong and weak inversion). Charge/capacitance equations
  (`b2moscap.c`) and noise (`b2noi.c`) are deferred.
- [x] **VDMOS** — power-MOSFET model, in modern ngspice. Confirmed in
  scope. Implemented in [thevenin/src/vdmos.rs](../thevenin/src/vdmos.rs)
  with built-in body diode + Miller-region Cgd; dispatched at MNA stamping
  time by inspecting the model's IR `DeviceType::Vdmos` / `Pvdmos` rather
  than a LEVEL number.
- [~] **HiSIM** (bulk) — surface-potential-based MOSFET (LEVEL=68).
  **Faithful I-V core landed 2026-07-02** (`thevenin/src/hisim.rs`, port
  plan Phases 2+3): zone D1/D2/D3 `Ps0` Newton solve, `Vdseff` DDLT clamp,
  drain-end `Psl` solve, drift+diffusion `Idd`, universal mobility with
  velocity saturation, SCE multi-level Newton loop (CORECIP=1), pocket
  dVthLP/dVthSC/dVthW, CLM `Lred`. Verified against real ngspice-45 golden
  sweeps to ≤0.0011% max rel-err (idvds/idvgs/idvbs); all scaffold
  `#[ignore]`s removed. `gm/gds/gmbs` by finite-difference of the forward
  eval. Still deferred: terminal charges/AC (Phase 4), Isub/GIDL/STI,
  CODEP depletion mode, noise.
- [~] **HiSIMHV** (LEVEL=73) — currently dispatches into the same
  simplified HiSIM DC core. High-voltage extensions (RDRIFT region,
  body resistance, breakdown) not yet modelled. Users requiring HV
  physics should use VDMOS until the HV core lands.
- [x] **Full device enumeration pass** (decided 2026-06-29). Audited all 57
  directories in `ngspice-upstream/src/spicelib/devices/` against thevenin's
  device set. Outcome by class:
  - **Implemented** (covered, possibly partial): asrc (behavioral), bjt, vbic,
    bsim1, bsim2, bsim3 (=bsim3v32), bsim3soi_dd/fd/pd, bsim4 (=bsim4v7), cap,
    cccs, ccvs, cpl, csw, dio, hfet1 **and** hfet2 (`hfet.rs` level 5 + 6), ind,
    isrc, jfet (level 1), ltra, mes (MESFET Statz/Curtice), mesa, mos1, mos2,
    mos3, mos6, res, sw, tra (T), txl, urc, vccs, vcvs, vdmos, vsrc; hisim2 /
    hisimhv1 partial (see above).
  - **Out — BSIM version point-variants** selected by the `version=` model param
    within one LEVEL, not a distinct device: `bsim3v0`, `bsim3v1` (we ship the
    canonical BSIM3v3.2), `bsim4v5`, `bsim4v6` (we ship BSIM4v7). The `version=`
    param is parsed and ignored gracefully. Older point-releases are back-compat
    curiosities, not new physics.
  - **Out — CIDER numerical/TCAD devices** (PDE mixed-level device simulation, a
    separate ngspice subsystem, not compact models): `nbjt`, `nbjt2`, `ndev`,
    `numd`, `numd2`, `numos`. Firmly out of scope for a compact-model simulator.
  - **Deferred post-1.0 — genuinely-missing standalone compact models**, each
    with a covering alternative already shipping, so none blocks a 1.0 goal:
    `hicum2` (5.2 kLOC advanced bipolar — VBIC covers high-end bipolar),
    `mos9` (7.9 kLOC Philips MOS9 — MOS1/2/3/6 + BSIM cover real decks),
    `soi3` (7.5 kLOC STAG SOI — BSIM3SOI 55/56/57 covers SOI),
    `bsimsoi` (28.5 kLOC BSIMSOI 4.x — we have BSIM3SOI 3.x),
    `hisimhv2` (21.9 kLOC — hisimhv1 is already the partial HV path),
    `jfet2` (1.9 kLOC Parker-Skellern JFET L2 — JFET L1 covers the common case).
    A deck using any of these imports fine (`DeviceType::Other` preserves the
    kind) but won't stamp that device; revisit individually on real demand.
- [x] **All harness fixtures un-ignored — 107/107 passing, 0 skipped
  (2026-07-03).** `ignore.toml` is empty. How each fell:

    The old "chaotic cascade" was: CONSTKoverQ thermal voltage, PULSE

  - `bsim3soidd/RampVg2.cir` — un-ignored 2026-07-02 (debug=-1 quasi-static

  - `general/schmitt.cir` — un-ignored 2026-07-02 (bounded post-trigger

  - `hfet/inverter.cir` — un-ignored 2026-07-02 (reference regenerated from

  - `bsim1/test.cir` — un-ignored 2026-07-02: the ~1.4% near-miss was a

### A2. Analyses

- [x] `.op`, `.dc` (single + nested sweep), `.tran`, `.ac` (DEC/OCT/LIN)
- [x] `.noise`, `.tf`, `.sens` (DC), `.pz`
- [x] Multi-temperature sweep at the `thevenin::circuit::simulate` level
- [x] **`.meas` / `.measure`** — full surface: MAX/MIN/AVG/RMS/PP/INTEG/
  FIND/WHEN/TRIG-TARG/DERIV/PARAM plus the late additions ERR/ERR1/ERR2/
  ERR3 (relative/absolute/RMS per-sample error vs. constant or vector,
  with `MINVAL=` / `IGNORE=`), `IF '<arith>'` conditional gating
  (skip measurement when prior-result expression is zero), and
  `FILE=<path>` to append `name = value` lines to disk in addition to
  the in-memory `measurements` plot. The `PARAM=` arithmetic also covers
  comparisons (`< > <= >= == !=`), logical operators (`&& || !`), and the
  ternary pass/fail idiom `(a < b) ? 1 : 0` — in both the SPICE clause
  parser and native Cirq. Typed `MeasureExpr` and `MeasureSpec` in
  `cirq-ir/src/lib.rs`; evaluator in `thevenin/src/measure.rs`.
- [x] **`.four`** — DFT of the final fundamental period of the
  preceding `.tran` (DC + 9 harmonics + THD). Implementation lives in
  `thevenin/src/fourier.rs::four_analysis` with dispatch wired through
  `thevenin::circuit::simulate_four`.
- [x] **`.fft`** — windowed radix-2 Cooley-Tukey FFT over a
  user-selectable transient interval. Supports rectangular, Hann,
  Hamming, Blackman, and Bartlett windows; `npoints` is rounded up to
  the next power of two. Implementation lives in
  `thevenin/src/fourier.rs::fft_analysis`.
- [x] **AC `.sens`** — `run_ac_sens` in `thevenin/src/sens.rs` wraps the
  direct-method sensitivity algorithm around the complex AC solve: at each
  swept frequency it factors Y(ω) = G + jB, then for every R/C/L/V/I
  parameter records `delta_V/delta_p` via `z = -dY·x` (plus the b-vector
  perturbation for sources). Verified against the closed-form RC and RL
  transfer-function sensitivities at multiple sweep points
  (`thevenin/tests/sensitivity_ac.rs`); DEC, OCT, LIN sweeps all covered.
- **`.disto`** — small-signal distortion (HD2/HD3/IM2/IM3). **Deferred
  post-1.0.** Requires Distor1/Distor2/Distor3 callbacks on every
  nonlinear device model (diode, BJT, VBIC, every MOSFET level, BSIM
  family, JFET, MESFET, HFET, plus the newly-in-scope BSIM1/2,
  HiSIM/HV, VDMOS). Pure mechanical port from ngspice but very wide
  surface area; users wanting distortion analysis can use `.tran` +
  `.four`/`.fft` in the meantime.
- [ ] **`.pss`** — periodic steady-state. Not in mainline ngspice; out
  of scope.

### A3. `.options`

Currently parsed: GMIN, ABSTOL, RELTOL, VNTOL, TEMP, TNOM.

- [x] **ITL1/ITL2/ITL4/ITL5/ITL6** — iteration limits, wired from
  `.options` into `NrOptions`. ITL5==0 sentinel = unlimited (modern
  ngspice convention). `SRCSTEPS` accepted as an alias for ITL6.
- [x] **METHOD** = `trap` | `gear` | `euler`. Parsed from `.options`
  via `integration_method_from_netlist` /
  `integration_method_from_circuit`; threaded into `TranRunParams`.
  Gear (BDF2) requires a 2-step BE bootstrap to seed `voltage_prev` /
  `current_prev`; the rest of the run uses the user's preference.
  Note: device-charge equations (BJT/MOSFET intrinsic caps) fall back
  to BE under `METHOD=gear` because they don't track q(n-1) history
  yet — full BDF2 for charge devices is a post-1.0 follow-up. L/C
  use BDF2 properly.
- [x] **CHGTOL** — charge tolerance for capacitive LTE.
- [x] **GMINSTEPS** — surfaces the Gmin-stepping fallback as a `.options`
  knob. Default 10 matches ngspice `CKTnumGminSteps`; sentinel `0`
  disables Gmin stepping entirely. `GMINFACTOR` still open (our stepping
  is adaptive, so the factor knob is less load-bearing).
- [x] **TRTOL** — transient truncation tolerance. Wired to `NrOptions::trtol`
  (default 7.0); the transient LTE controller multiplies its budget by this
  knob. Parsed from `.options TRTOL=` on both Netlist and Circuit paths.
- [x] **PIVTOL / PIVREL** — sparse pivot thresholds. Stored on
  `NrOptions::{pivtol,pivrel}` and parsed from `.options`. **No-op:** faer's
  high-level sparse LU does not expose pivot thresholding; the values are
  retained for ngspice compatibility and a stderr warning fires when the
  user moves them away from the defaults.
- [x] **DEFAD / DEFAS / DEFL / DEFW** — MOSFET geometry defaults applied
  when an instance omits AD/AS/L/W. Parsed from `.options` on both
  Netlist and Circuit paths.
- [x] **RSHUNT** — node-to-ground shunt resistance. Default 0 (disabled);
  when non-zero adds `1/rshunt` to every non-ground NR Jacobian diagonal
  entry, matching ngspice `cktrshun.c`.
- [x] **GSHUNT** — node-to-ground shunt *conductance*, the conductance-valued
  twin of RSHUNT. Default 0 (disabled); when non-zero adds `gshunt` to every
  non-ground diagonal entry (composes additively with RSHUNT). Models the
  dominant load-time effect of ngspice's `CKTgshunt` (which also seeds
  `CKTdiagGmin` / the Gmin-stepping target). `NrOptions::gshunt`.
- [x] **NOOPITER** — when set, the OP solver skips the initial direct NR
  attempt and goes straight to Gmin stepping.
- [~] **NOOPALTER** — parsed and stored on `NrOptions`, but currently a
  no-op: the `.alter`-and-resolve path isn't wired through `NrOptions`
  yet, so skipping the OP re-solve on alter is deferred.
- [x] **SRCSTEPS** — aliased to ITL6 above.
- [x] **GMINPRIORITY** — when set, the OP solver runs Gmin stepping
  first and falls back to direct NR if Gmin fails. Inverts the default
  direct→Gmin order.
- [x] **`scale`** — geometry scale factor parsed and stored in
  `Circuit::options`. Geometric application across MOSFET dimensions
  deferred (no fixture exercises it yet).
- [x] **Full `.options` survey** — one pass over ngspice's authoritative
  settable set (`OPTsetParm` in `ngspice-upstream/src/spicelib/analysis/cktsopt.c`,
  which is the real `.options` parser contract; the manual §15.1.1 list is a
  documented subset). Every key is now decided. **Implemented** (above):
  GMIN, GSHUNT, ABSTOL, RELTOL, VNTOL, TRTOL, CHGTOL, PIVTOL/PIVREL (no-op),
  TEMP, TNOM, ITL1/2/4/5/6, SRCSTEPS, GMINSTEPS, NOOPITER, NOOPALTER,
  GMINPRIORITY, RSHUNT, DEFAD/DEFAS/DEFL/DEFW, METHOD, `scale`. The remainder
  are **explicitly punted** with rationale:
  - *Solver-backend selectors — N/A (we use `faer`, not ngspice's Sparse1.3/KLU):*
    `SPARSE`, `KLU`, `KLU_MEMGROW_FACTOR`. (`PIVTOL`/`PIVREL` are accepted but
    no-op for the same reason.)
  - *Frontend / output / diagnostic `set`-style vars (same class as the
    interactive-shell punt at the top of this doc):* `ACCT`, `NOACCT`, `LIST`,
    `NODE`, `NOMOD`, `NOPAGE`, `NUMDGT`, `OPTS`, `WARN`, `MAXWARNS`,
    `SAVECURRENTS`, `SEED`, `INDVERBOSITY`, `KEEPOPINFO`.
  - *XSPICE event-engine internals (compiled-in XSPICE stays, but the
    event-iteration knobs are out of scope):* `MAXEVTITER`, `MAXOPALTER`.
  - *Niche convergence/integration tuning — `GMIN`/`GMINSTEPS`/`TRTOL`/`CHGTOL`/
    `RSHUNT`/`GSHUNT` cover the load-bearing cases; revisit only if a real deck
    needs one:* `GMINFACTOR` (our Gmin stepping is adaptive), `CSHUNT`
    (transient-only node-to-ground cap; needs companion plumbing), `MINBREAK`,
    `MAXORD` (we run fixed BDF2 for Gear), `XMU` (trap/Gear blend), `NEWTRUNC`,
    `LTERELTOL`/`LTEABSTOL`/`LTETRTOL` (fine LTE tuning), `NODEDAMPING`/`ABSDV`/
    `RELDV`, `CONVLIMIT`/`CONVSTEP`, `RAMPTIME` (source-ramp continuation; see
    A5 pseudo-transient), `NOOPAC`, `EPSMIN`, `BYPASS` (companion-model bypass
    exists internally; no user toggle), `ITL3` (obsolete in ngspice).
  - *Legacy device-compat flags:* `BADMOS3` (MOS3 kink compat), `OLDLIMIT`
    (old MOS limiting), `TRYTOCOMPACT` (LTRA history compaction), `COPYNODESETS`,
    `DEFM` (MOSFET default `m`; decks specify it explicitly).

  Unrecognised `.options` keys are ignored silently rather than warned —
  `TEMP`/`TNOM`/`scale` are handled on other parse paths, so a blanket
  unknown-key warning in `nr_options_from_circuit` would fire false positives.

### A4. `.control` interpreter

Already implemented in `thevenin-control`: run / op / dc / ac / tran /
sens / noise / pz / tf, set, let, echo, print, if/else, foreach, quit,
alter (incl. plain form `alter v1=-5`), compose, strcmp, define,
setplot, eprint, stop when, resume.

Missing pieces that real netlists actually use:

- [x] **`save`** as a control command (distinct from `.save` directive).
- [x] **`write`** for raw-file output from inside `.control` —
  `Statement::Write { file, vectors }` parsed and dispatched via
  `execute_write` in `thevenin-control/src/exec.rs`; honours `.raw`/`.csv`
  extensions and the `set filetype = ascii|binary` convention.
- [x] **Vector-arithmetic operators in `print`** — `.+`, `.*`, `.-`, `./`
  (treated as element-wise synonyms for the bare versions), range indexing
  `v[i:j]`, and scalar broadcast (`v(out) * 2`). Element-wise pair forms
  reuse the existing broadcast in [`vecexpr.rs`](../thevenin-control/src/vecexpr.rs);
  the dotted forms are decoded in the tokenizer.
- [x] **`measure`** as a control command (post-`run`), not just `.meas`
  directive. Same evaluator; different lifecycle — see
  `Statement::Measure` in
  [`cirq-ir/src/control.rs`](../cirq-ir/src/control.rs) and
  `execute_measure` in
  [`thevenin-control/src/exec.rs`](../thevenin-control/src/exec.rs).
- [x] **`while`** — standard structured loop with `MAX_LOOP_ITERS=10_000` cap.
- [x] **`repeat N`** loop.
- [x] **`source`** to include a sub-script. `Statement::Source` lives in
  [`cirq-ir/src/control.rs`](../cirq-ir/src/control.rs); the executor reads
  the file relative to CWD, parses it as a `.control` block, runs the
  statements in the current `SimContext`, and guards against recursive
  includes with a `HashSet<PathBuf>` on the context.

Explicit punts: `cd`, `pwd`, `history`, `listing`, `shell`, anything
gnuplot.

### A5. Convergence and numerics

- [x] Sparse LU via `faer`, with symbolic reuse across NR / timesteps.
- [x] Gmin stepping, source stepping, voltage limiting (pnjlim/fetlim),

- [x] Dense FullPivLu fallback for small matrices.
- [ ] **Markowitz / threshold-pivot ordering tuning** — currently
  delegated entirely to faer; expose a knob for ill-conditioned MOSFET
  matrices.
- [ ] **Pseudo-transient continuation** as an explicit fallback when
  Gmin + source stepping both fail (ngspice has this).
- [x] **Iterative refinement** after solve. Surfaced as the

  pass — cheap insurance against ill-conditioning. Not on by default
  pending wider regression sweeps.

## Goal B — Cirq as a feature-complete source language

### B1. Element syntax

Per `docs/cirq-spec/04-elements.md` + `cirq-ir/src/lib.rs:118`:

- [x] resistor, capacitor, inductor, coupling
- [x] voltage / current sources with full waveform syntax
- [x] dependent sources (vcvs, vccs, ccvs, cccs)
- [x] diode, npn/pnp, nmos/pmos, njfet/pjfet, nmesfet/pmesfet, mesa,
  hfet via model dispatch
- [x] tline, txl, coupled_line, xspice, behavioral
- [x] **switch syntax** for S / W. Importer round-trips both
  voltage-controlled (`S n+ n- nc+ nc- model [ON|OFF]`) and
  current-controlled (`W n+ n- vsense model [ON|OFF]`) forms into the
  shared `IrElementKind::Switch { kind, control }` IR. Native Cirq source
  syntax for switches still goes through the `code "control"` block or
  the SPICE-import path; positional Cirq syntax not yet defined.
- [x] **urc** syntax — **implemented.** Native `urc` element, e.g.
  `U1: urc(in -> out, model: rcline, len: 1000, lumps: 16)`. URC is a macro: it
  expands at lowering time into the same R/C(/D) ladder the SPICE importer
  produces (no new `ElementKind`, no simulator change). One element form
  supports both a `model rcline: urc {…}` card and inline per-length params
  (`rperl`/`cperl`/`fmax`/`k`/`isperl`/`rsperl`), with inline overriding the
  model; `len` is required, `lumps`/`gnd` optional (ground defaults to `gnd`).
  The expansion arithmetic is shared with the importer via `cirq_ir::urc::plan`,
  so native and imported URCs are byte-identical. See `cirq-frontend`
  `lower_urc_element` and `cirq-frontend/tests/urc.rs`.

### B2. Expressions

- [x] Arithmetic, comparison, logical, ternary-via-`if`-function plans.
- [x] User-defined functions (`func`), let bindings.
- [x] SI unit literals, typed real/int/bool/string/net.
- [x] Built-in: abs, sqrt, exp, ln, log, log10, pow, sin, cos, tan, min,
  max.
- [x] **`atan`, `atan2`, `asin`, `acos`, `sinh`, `cosh`, `tanh`**.
- [x] **`sgn`, `ceil`, `floor`, `int`** (int truncates toward zero, fixed
  in the importer's evaluator too).
- [x] **`db(x)`, `db20(x)`**.
- [x] **`limit(x, lo, hi)`** — clamps, errors on `lo > hi`.
- [x] **Ternary `cond ? t : e`** — operator form lands as the standard
  shape (function `if(c, t, e)` and `if/else` statement form remain
  available). Right-associative, lower precedence than `||`. Grammar
  regenerated via tree-sitter CLI; AST gains
  `Expr::Ternary { cond, then_expr, else_expr }`; lowering emits a
  SPICE-compatible `(c)?(t):(e)` string for behavioural sources so the
  brace evaluator binds it at simulation time, and direct param-time
  evaluation short-circuits the unused branch in `eval_expr`. The same
  operator carries into measurement expressions via `MeasArith::Cond`
  (`cirq-ir`), so `(vout_diff < 100k) ? 1 : 0` works in `measure` bodies too.
- [x] **Simulation-context constants** — `temper`, `time`, `freq`,
  `hertz`. `temper` resolves at parameter-evaluation time from the
  circuit's static `temp` directive (defaulting to 27 °C / TNOM); the
  three time-varying constants pass through `expr_to_spice_string`
  unchanged and are bound at simulation time inside
  `evaluate_bsrc_expr_with_ctx` via a new `SimContext` carried on
  `DeviceVoltageState` (transient: `time` + `temper`) and on the AC
  cache (one-shot `freq` / `hertz` + `temper`). AC small-signal
  contribution stays as the Jacobian only — constant `freq`-dependent
  bias terms linearise to zero, matching ngspice's documented
  behaviour for `.ac` B-sources.
- [x] **Conditional parameter selection** at compile time — native
  `if <cond> { ... } elseif <cond> { ... } else { ... }` brace blocks at
  circuit and module scope (mirroring SPICE `.if`). Resolved during pass 1 of
  `ir_lower` by folding each condition against the params known so far; only
  the taken branch's items reach the IR. Bodies hold any circuit item,
  including nested conditionals. Conditions are constant expressions over
  params/literals — numeric, boolean, and string (`==`/`!=`) comparisons all
  fold. `conditional_decl` in the grammar; `CircuitItem::Conditional` in the
  AST.

### B3. Native analysis directives

- [x] op, dc, ac, tran, noise, pz, sens, tf surface in
  `cirq-ir/src/lib.rs::Analysis`.
- [x] `.meas` is typed in IR (`MeasureExpr`, recently typed).
- [x] **Native Cirq syntax for `.meas`** — two forms. The expression form
  `measure <kind> <name> = <expr>` is first-class Cirq: probe functions
  (`max`/`min`/`avg`/`rms`/`pp`, `integ`, `find`, `when`, `deriv`, `delay`
  with `cross(...)` events) take named windowing/edge args, and any other
  expression is derived/conditional arithmetic over earlier measurements
  (comparisons, `&&`/`||`/`!`, ternary). The legacy block form
  `measure <kind> "name" { spec: "..." }` remains as an escape hatch. Both
  lower to the same typed `MeasureExpr`; the expression form synthesizes a
  canonical clause string (`MeasureExpr::to_spec_string`) so native and
  SPICE-imported measurements round-trip losslessly.
- [x] **`analysis four { ... }`** — native Fourier block (`fundamental:`,
  `output:` single or list, optional `harmonics:`). Lowers to the same
  `Analysis::Four` IR as imported `.four`; `lower_four_analysis` in `ir_lower`.
- [x] **`analysis fft { ... }`** — native FFT block (`output:`, optional
  `start:`/`stop:`/`npoints:`/`window:`/`format:`). Lowers to `Analysis::Fft`;
  `lower_fft_analysis` in `ir_lower`. Both are spelled as analysis kinds (no new
  grammar), consistent with `analysis tran`/`ac`/etc., and post-process the
  preceding `analysis tran`.

### B4. Embedded-language blocks (the `code "X" { ... }` mechanism)

Cirq's design for control flow is **not** to invent native Cirq control
syntax. Instead it has the generic embedded-language block:

```
code "control" {
    ... statements in the named language ...
}
```

(Defined in `cirq-grammar/grammar.js:207` as `code_decl`; stored in IR as
`Circuit::code_blocks: Vec<CodeBlock>` at `cirq-ir/src/lib.rs:42`.)

The point is extensibility: the same mechanism can later host an embedded
JS engine, a Python block, a domain-specific DSL, whatever — without
adding new Cirq syntax each time.

- [x] `code "control" { ... }` parses and lowers to a `CodeBlock`.
- [x] `control` language is handled by `thevenin-control`'s typed
  AST (let, echo, if/else, foreach, set, alter, print, run, stop when,
  resume, quit; recent typed control-AST commit 7ce12c3).
- [x] **Configurable language registry.** Implemented as two halves along the
  crate-dependency seam (cirq-frontend can't depend on thevenin-control):
  - **Compile time** — `cirq_frontend::LanguageRegistry` (accepted-tag set,
    default `{"control"}`). `compile_with_languages` /
    `compile_file_with_languages` validate every `code "lang" {}` block; an
    unregistered tag is **rejected with a spanned diagnostic** (previously
    silently dropped). Validation lives in the `CircuitItem::Code` arm of
    `cirq-frontend/src/ir_lower.rs`.
  - **Execution time** — `thevenin_control::language::{LanguageHandler,
    LanguageRegistry}` (tag → handler). Default registers the built-in
    `ControlHandler`. `execute_code_blocks_ir(circuit, &registry)` routes each
    block through its handler; `execute_control_block_ir` is now a back-compat
    wrapper. `LanguageRegistry::tags()` lets a host derive the frontend registry
    so the two halves stay in sync.
- [x] **`while`, `repeat`** statements in the `control` language —
  `Statement::While` / `Statement::Repeat` lowered in
  `cirq-ir/src/control_lower.rs` and executed in `thevenin-control/src/exec.rs`.
- [x] Document the registry interface and the handler contract —
  `docs/architecture/language-registry.md` (input: verbatim lines + optional
  pre-parsed AST + live `SimContext`; output: side effects on the context —
  plots, output, exit code). Also summarised in
  `docs/cirq-spec/03-circuits-and-modules.md`.

### B5. Modules, parameters, hierarchy

- [x] Module definitions with typed ports, positional + named
  instantiation, parameter overrides at call site, inline modules,
  nested modules.
- [x] Imports with relative paths, deduplication, circular detection.
- [x] `.global` keyword for shared nets.
- [x] **Pin-by-name** connection syntax — `inst: m1(d: n1, g: n2, s: gnd,
  b: gnd)` works via the shared `named_argument` rule; verified parsing and
  lowering (e.g. `M1: nmos(d: out, g: in, s: gnd, b: gnd, model: nch)`).
- [x] **Port arrays / variable-width ports** — **implemented.** Bus ports
  `port d[8]: in` and param-driven `port d[width]: in`, single-line references
  `d[2]`, and whole-bus connections (`d: caller_bus`). A bus is sugar for the
  scalar nets `d.0 … d.N-1`: `d[i]` lowers to net `d.i`, and a whole-bus port
  binding carries every referenced line through to the caller's `bus.i` nets
  (lazy index remap, so no width arithmetic at the binding site). Grammar:
  optional `[width]` on `port_decl` + a `subscripted_net` rule; AST `NetRef`;
  elaboration in `cirq-frontend` `resolve_net_ref` / the module-inst remap. See
  `cirq-frontend/tests/buses.rs`.
  - **Known limitation:** Cirq has no compile-time loop (`for`/`generate`), so a
    `port d[width]` module cannot *generate* width-many elements — buses are for
    bundling, pass-through, and explicit per-line indexing. A `generate`-style
    loop is a candidate post-1.0 follow-up; range slices `d[0:4]` are likewise
    deferred (the `[ ]` index syntax is in, slices are not).

### B6. Comments and lexical

- [x] `//` line, `/* */` block (nesting).
- [x] **Decision: no SPICE comments.** A leading `*` is a syntax error in Cirq,
  not a comment — paste SPICE through the importer, not into Cirq source. `;`
  is already insignificant whitespace (an optional statement terminator), not
  an inline-comment marker. Keeps the Cirq/SPICE boundary clean. Documented in
  `docs/cirq-spec/01-lexical.md`.

- [x] Audited `docs/cirq-spec/` for stale "draft"/"future" labels. Updated

  `02-types-and-values.md`, and the `.meas` advanced features (ERR/IF/FILE)

  documented, and bus/port arrays now ship (see B5). Remaining "future" notes

  `generate`-style loops) are genuinely unimplemented and left marked.
- [x] Bumped `00-overview.md` from "0.2.0-draft / Implementation in progress"
  to "1.0 / Stable".

## Decisions log

All resolved 2026-05-23:

1. BSIM1 + BSIM2 → **in**.
2. HiSIM / HiSIMHV → **in**.
3. VDMOS → **in**.
4. `.four` / `.fft` → **in**.
5. `.disto` → **deferred post-1.0**. Touches every nonlinear device
   model; defer rather than block the release.
6. AC-mode `.sens` → **in**.
7. HSPICE / PSPICE dialect coverage → **out**. Anything beyond what stock
   ngspice itself parses is post-1.0.
8. Native Cirq control syntax → **no separate `control { ... }` block**.
   Reuse the existing `code "control" { ... }` embedded-language
   mechanism (keyword stays `code`), and make the language registry
   configurable so third parties can register additional language
   handlers (JS, Python, custom DSLs).
9. Switches (S, W) → **in**.
10. URC + other "weird MOSFET" variants (HICUM2, NUMOS, etc.) → **in** by
    extension. Needs an explicit enumeration pass against
    `ngspice-upstream/src/spicelib/devices/` before sizing the work.
