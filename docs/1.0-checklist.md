# Thevenin / Cirq 1.0 Readiness Checklist

Draft, 2026-05-23. The three release goals:

1. **Thevenin** is practically compatible with ngspice within numerical
   tolerances on real-world circuits.
2. **Cirq** is a feature-complete source language replacement for SPICE —
   anything an engineer would write in SPICE, they can write natively in
   Cirq.
3. **Cirq's SPICE importer** accepts any arbitrary SPICE netlist a user
   might throw at it without bespoke pre-massaging.

## Status snapshot

- `thevenin` 0.3.0, `thevenin-types` 0.3.0, everything else 0.1.x.
- 1010+ workspace tests passing, 6 ignored. Clippy / fmt clean.
- Stage 4 (Netlist → Cirq IR retirement) **complete**: only public
  simulator surface is `thevenin::circuit::simulate(&Circuit)` and the
  per-analysis variants. `.control` interpreter runs on Circuit. `--legacy`
  flag gone. See `migration/cirq-adoption-plan.md` for the historical arc.

## Out of scope for 1.0

Explicit non-goals so we don't accidentally chase them:

- Dynamic library code-model loading (`cm` shared objects, runtime XSPICE
  plug-ins). Compiled-in XSPICE models via the registry stay.
- Interactive shell features: command history, `cd`/`pwd`, `shell`,
  gnuplot integration, persistent `set`/`unset` state.
- **HSPICE / PSPICE dialect support.** Real netlists from these tools will
  fail to import; users translate or run them through their own tool's
  preprocessor first. Anything beyond what stock ngspice itself parses is
  post-1.0.
- Co-simulation (Verilog-A, TCL, external solvers).

## Goal A — Thevenin practical ngspice compatibility

### A1. Device models

- [x] Resistor, capacitor, inductor, mutual coupling (K)
- [x] Independent sources (V, I) with DC, AC, all 6 waveforms
- [x] Dependent sources (E, F, G, H)
- [x] Behavioral sources (B) with V=/I= expression modes
- [x] Diode
- [x] BJT level 1 (Gummel-Poon)
- [x] BJT level 4 (VBIC)
- [x] MOSFET levels 1, 2, 3, 6
- [x] BSIM3v3 (level 49)
- [x] BSIM4 (level 14 / 54)
- [x] BSIM3SOI FD, PD, DD (levels 55/56/57)
- [x] JFET
- [x] MESFET, HFET, generic MESA family
- [x] LTRA, TXL, CPL, T (ideal lossless) transmission lines
- [x] XSPICE code models (A element, compiled-in via registry)
- [x] **Switches (S, W)** — voltage- and current-controlled. Hysteretic
  conductance via `thevenin/src/switch.rs`; stamped through the NR loop
  with latched state persisting across iterations/timesteps. Supported
  models: `SW`/`VSWITCH` and `CSW`/`ISWITCH` (`Vt`/`It`, `Vh`/`Ih`,
  `Ron`, `Roff`).
- [x] **URC (uniform RC transmission line)** — implemented as a SPICE
  importer macro expansion. `Uname n1 n2 ngnd model L=len [N=lumps]` +
  `.model NAME URC (...)` expands into N stages of R/C (or R/C/D when
  `ISPERL > 0`) at import time, matching ngspice's `urcsetup.c`. The
  simulator never sees a URC element. See
  [`cirq-spice-import/src/lib.rs`](../cirq-spice-import/src/lib.rs)
  `expand_urc`.
- [x] **BSIM1** — ported from ngspice (`b1ld.c`/`b1eval.c`/`b1temp.c`). Implemented in [thevenin/src/bsim1.rs](../thevenin/src/bsim1.rs). DC + NR companion path with full process-parameter table including `_L`/`_W` size binning; AC charge/noise out of scope for the 1.0 cut.
- [x] **BSIM2** — ngspice LEVEL=5 port. Implemented in
  [thevenin/src/bsim2.rs](../thevenin/src/bsim2.rs); ports `b2eval.c` (DC
  drain-current and derivatives, threshold via vfb/k1/k2, mobility
  Ua/Ub/U1, subthreshold n0/nb/nd, impact-ionisation Ai/Bi, cubic-spline
  blend between strong and weak inversion). Charge/capacitance equations
  (`b2moscap.c`) and noise (`b2noi.c`) are deferred.
- [x] **VDMOS** — power-MOSFET model, in modern ngspice. Confirmed in
  scope. Implemented in [thevenin/src/vdmos.rs](../thevenin/src/vdmos.rs)
  with built-in body diode + Miller-region Cgd; dispatched at MNA stamping
  time by inspecting the model's IR `DeviceType::Vdmos` / `Pvdmos` rather
  than a LEVEL number.
- [x] **HiSIM** (bulk) — surface-potential-based MOSFET (LEVEL=68).
  Implementation lives in `thevenin/src/hisim.rs`. DC + companion-model
  NR path complete with inner NR for ψs. AC small-signal caps, noise,
  and intrinsic Cgg/Cgd charge equations deferred.
- [~] **HiSIMHV** (LEVEL=73) — currently dispatches into the same
  simplified HiSIM DC core. High-voltage extensions (RDRIFT region,
  body resistance, breakdown) not yet modelled. Users requiring HV
  physics should use VDMOS until the HV core lands.
- [ ] **Other "weird MOSFET" variants** in ngspice that we haven't audited
  yet (HICUM2, NUMOS, etc.) — assumed in scope by extension; explicit
  enumeration pass needed before estimating effort.
- [x] Adjust the 6 currently-ignored harness fixtures:
  - `bsim3soidd/RampVg2.cir` — CAPMOD=3 body-floating Vbs gap.
    Investigate body-junction current balance + cap-coupling slope.
    Tracked in `100-percent-plan.md` and `future-work.md`.
  - `general/rtlinv.cir`, `general/schmitt.cir` — transient timing cascade.
    Architectural; revisit only if a wider class of circuits fails.
  - `hfet/inverter.cir` — closed: ngspice reference has a confirmed bug.
    Keep ignored with the writeup in place.
  - `bsim1/test.cir`, `bsim2/test.cir` — unblock once BSIM1 / BSIM2
    land.

### A2. Analyses

- [x] `.op`, `.dc` (single + nested sweep), `.tran`, `.ac` (DEC/OCT/LIN)
- [x] `.noise`, `.tf`, `.sens` (DC), `.pz`
- [x] Multi-temperature sweep at the `thevenin::circuit::simulate` level
- [x] **`.meas` / `.measure`** — full surface: MAX/MIN/AVG/RMS/PP/INTEG/
  FIND/WHEN/TRIG-TARG/DERIV/PARAM plus the late additions ERR/ERR1/ERR2/
  ERR3 (relative/absolute/RMS per-sample error vs. constant or vector,
  with `MINVAL=` / `IGNORE=`), `IF '<arith>'` conditional gating
  (skip measurement when prior-result expression is zero), and
  `FILE=<path>` to append `name = value` lines to disk in addition to
  the in-memory `measurements` plot. Typed `MeasureExpr` and
  `MeasureSpec` in `cirq-ir/src/lib.rs`; evaluator in
  `thevenin/src/measure.rs`.
- [x] **`.four`** — DFT of the final fundamental period of the
  preceding `.tran` (DC + 9 harmonics + THD). Implementation lives in
  `thevenin/src/fourier.rs::four_analysis` with dispatch wired through
  `thevenin::circuit::simulate_four`.
- [x] **`.fft`** — windowed radix-2 Cooley-Tukey FFT over a
  user-selectable transient interval. Supports rectangular, Hann,
  Hamming, Blackman, and Bartlett windows; `npoints` is rounded up to
  the next power of two. Implementation lives in
  `thevenin/src/fourier.rs::fft_analysis`.
- [x] **AC `.sens`** — `run_ac_sens` in `thevenin/src/sens.rs` wraps the
  direct-method sensitivity algorithm around the complex AC solve: at each
  swept frequency it factors Y(ω) = G + jB, then for every R/C/L/V/I
  parameter records `delta_V/delta_p` via `z = -dY·x` (plus the b-vector
  perturbation for sources). Verified against the closed-form RC and RL
  transfer-function sensitivities at multiple sweep points
  (`thevenin/tests/sensitivity_ac.rs`); DEC, OCT, LIN sweeps all covered.
- **`.disto`** — small-signal distortion (HD2/HD3/IM2/IM3). **Deferred
  post-1.0.** Requires Distor1/Distor2/Distor3 callbacks on every
  nonlinear device model (diode, BJT, VBIC, every MOSFET level, BSIM
  family, JFET, MESFET, HFET, plus the newly-in-scope BSIM1/2,
  HiSIM/HV, VDMOS). Pure mechanical port from ngspice but very wide
  surface area; users wanting distortion analysis can use `.tran` +
  `.four`/`.fft` in the meantime.
- [ ] **`.pss`** — periodic steady-state. Not in mainline ngspice; out
  of scope.

### A3. `.options`

Currently parsed: GMIN, ABSTOL, RELTOL, VNTOL, TEMP, TNOM.

- [x] **ITL1/ITL2/ITL4/ITL5/ITL6** — iteration limits, wired from
  `.options` into `NrOptions`. ITL5==0 sentinel = unlimited (modern
  ngspice convention). `SRCSTEPS` accepted as an alias for ITL6.
- [x] **METHOD** = `trap` | `gear` | `euler`. Parsed from `.options`
  via `integration_method_from_netlist` /
  `integration_method_from_circuit`; threaded into `TranRunParams`.
  Gear (BDF2) requires a 2-step BE bootstrap to seed `voltage_prev` /
  `current_prev`; the rest of the run uses the user's preference.
  Note: device-charge equations (BJT/MOSFET intrinsic caps) fall back
  to BE under `METHOD=gear` because they don't track q(n-1) history
  yet — full BDF2 for charge devices is a post-1.0 follow-up. L/C
  use BDF2 properly.
- [x] **CHGTOL** — charge tolerance for capacitive LTE.
- [x] **GMINSTEPS** — surfaces the Gmin-stepping fallback as a `.options`
  knob. Default 10 matches ngspice `CKTnumGminSteps`; sentinel `0`
  disables Gmin stepping entirely. `GMINFACTOR` still open (our stepping
  is adaptive, so the factor knob is less load-bearing).
- [x] **TRTOL** — transient truncation tolerance. Wired to `NrOptions::trtol`
  (default 7.0); the transient LTE controller multiplies its budget by this
  knob. Parsed from `.options TRTOL=` on both Netlist and Circuit paths.
- [x] **PIVTOL / PIVREL** — sparse pivot thresholds. Stored on
  `NrOptions::{pivtol,pivrel}` and parsed from `.options`. **No-op:** faer's
  high-level sparse LU does not expose pivot thresholding; the values are
  retained for ngspice compatibility and a stderr warning fires when the
  user moves them away from the defaults.
- [ ] **DEFAD / DEFAS / DEFL / DEFW** — MOSFET geometry defaults.
- [ ] **TRTOL** — transient truncation tolerance.
- [ ] **PIVTOL / PIVREL** — sparse pivot thresholds.
- [x] **DEFAD / DEFAS / DEFL / DEFW** — MOSFET geometry defaults applied
  when an instance omits AD/AS/L/W. Parsed from `.options` on both
  Netlist and Circuit paths.
- [x] **RSHUNT** — node-to-ground shunt resistance. Default 0 (disabled);
  when non-zero adds `1/rshunt` to every non-ground NR Jacobian diagonal
  entry, matching ngspice `cktrshun.c`.
- [x] **NOOPITER** — when set, the OP solver skips the initial direct NR
  attempt and goes straight to Gmin stepping.
- [~] **NOOPALTER** — parsed and stored on `NrOptions`, but currently a
  no-op: the `.alter`-and-resolve path isn't wired through `NrOptions`
  yet, so skipping the OP re-solve on alter is deferred.
- [x] **SRCSTEPS** — aliased to ITL6 above.
- [x] **GMINPRIORITY** — when set, the OP solver runs Gmin stepping
  first and falls back to direct NR if Gmin fails. Inverts the default
  direct→Gmin order.
- [x] **`scale`** — geometry scale factor parsed and stored in
  `Circuit::options`. Geometric application across MOSFET dimensions
  deferred (no fixture exercises it yet).
- [ ] Survey ngspice manual §15.1.1 once and check off / explicitly punt
  every remaining option in one pass — too many to enumerate
  individually here.

### A4. `.control` interpreter

Already implemented in `thevenin-control`: run / op / dc / ac / tran /
sens / noise / pz / tf, set, let, echo, print, if/else, foreach, quit,
alter (incl. plain form `alter v1=-5`), compose, strcmp, define,
setplot, eprint, stop when, resume.

Missing pieces that real netlists actually use:

- [x] **`save`** as a control command (distinct from `.save` directive).
- [ ] **`write`** for raw-file output from inside `.control` (depends on
  A6 raw-file support).
- [ ] **Vector-arithmetic operators in `print`** — `.+`, `.*`, etc., plus
  ranges and indexing. Common in interactive post-processing.
- [ ] **`measure`** as a control command (post-`run`), not just `.meas`
  directive. Same evaluator; different lifecycle.
- [x] **`while`** — standard structured loop with `MAX_LOOP_ITERS=10_000` cap.
- [x] **`repeat N`** loop.
- [ ] **`source`** to include a sub-script.

Explicit punts: `cd`, `pwd`, `history`, `listing`, `shell`, anything
gnuplot.

### A5. Convergence and numerics

- [x] Sparse LU via `faer`, with symbolic reuse across NR / timesteps.
- [x] Gmin stepping, source stepping, voltage limiting (pnjlim/fetlim),
  MODEINITJCT/MODEINITFLOAT, companion-model bypass.
- [x] Dense FullPivLu fallback for small matrices.
- [ ] **Markowitz / threshold-pivot ordering tuning** — currently
  delegated entirely to faer; expose a knob for ill-conditioned MOSFET
  matrices.
- [ ] **Pseudo-transient continuation** as an explicit fallback when
  Gmin + source stepping both fail (ngspice has this).
- [x] **Iterative refinement** after solve. Surfaced as the
  `NrOptions::iterative_refinement` flag (default `false` to preserve
  byte-for-byte behaviour) and as `.options iterative_refinement=1`. When
  enabled, every sparse/dense LU solve performs one residual-and-correct
  pass — cheap insurance against ill-conditioning. Not on by default
  pending wider regression sweeps.

### A6. Output formats

Today: text "batch" output mirroring ngspice's stdout, plus internal
`SimResult` / `SimPlot`.

- [x] **ngspice raw file (binary)** — the canonical interchange format.
  Required for users plugging us into existing tooling (KiCad, plotting
  scripts, regression frameworks). Lives in
  `thevenin/src/raw_output.rs::write_binary_raw`; little-endian by
  contract so files round-trip across machines.
- [x] **ngspice raw file (ASCII)** — same format, ASCII variant. Shares
  the header writer with the binary path.
- [x] **CSV** — convenience output; trivial once raw is in place.
  `write_csv` emits the first plot only.
- [x] Wire to `write` / `wrdata` control commands (see A4). `write
  [filename] [vec_list]` is implemented; filename extension picks
  format and the `filetype` set var selects ASCII vs binary raw.
- [x] Document the format in `docs/architecture/`. See
  `docs/architecture/raw-file-format.md`.

- [x] **Move `docs/cirq-plan/` and `docs/migration/` to `docs/archive/`**.

## Goal B — Cirq as a feature-complete source language

### B1. Element syntax

Per `docs/cirq-spec/04-elements.md` + `cirq-ir/src/lib.rs:118`:

- [x] resistor, capacitor, inductor, coupling
- [x] voltage / current sources with full waveform syntax
- [x] dependent sources (vcvs, vccs, ccvs, cccs)
- [x] diode, npn/pnp, nmos/pmos, njfet/pjfet, nmesfet/pmesfet, mesa,
  hfet via model dispatch
- [x] tline, txl, coupled_line, xspice, behavioral
- [x] **switch syntax** for S / W. Importer round-trips both
  voltage-controlled (`S n+ n- nc+ nc- model [ON|OFF]`) and
  current-controlled (`W n+ n- vsense model [ON|OFF]`) forms into the
  shared `IrElementKind::Switch { kind, control }` IR. Native Cirq source
  syntax for switches still goes through the `code "control"` block or
  the SPICE-import path; positional Cirq syntax not yet defined.
- [ ] **urc** syntax (only if A1 includes URC).

### B2. Expressions

- [x] Arithmetic, comparison, logical, ternary-via-`if`-function plans.
- [x] User-defined functions (`func`), let bindings.
- [x] SI unit literals, typed real/int/bool/string/net.
- [x] Built-in: abs, sqrt, exp, ln, log, log10, pow, sin, cos, tan, min,
  max.
- [x] **`atan`, `atan2`, `asin`, `acos`, `sinh`, `cosh`, `tanh`**.
- [x] **`sgn`, `ceil`, `floor`, `int`** (int truncates toward zero, fixed
  in the importer's evaluator too).
- [x] **`db(x)`, `db20(x)`**.
- [x] **`limit(x, lo, hi)`** — clamps, errors on `lo > hi`.
- [ ] **Ternary `cond ? t : e`** — spec mentions plan-only. Settle the
  syntax (operator vs `if(c, t, e)` function vs `if/else` expression)
  and implement.
- [ ] **Simulation-context constants** — `temper`, `time`, `freq`,
  `hertz`. Needed for portable model parameters and behavioural
  sources.
- [ ] **Conditional parameter selection** at parse time (`if/elseif/else/
  endif` at module scope, mirroring SPICE `.if`).

### B3. Native analysis directives

- [x] op, dc, ac, tran, noise, pz, sens, tf surface in
  `cirq-ir/src/lib.rs::Analysis`.
- [x] `.meas` is typed in IR (`MeasureExpr`, recently typed).
- [x] **Native Cirq syntax for `.meas`** — `measure <kind> "name" { spec:
  "..." }` block parses via the tree-sitter grammar, lowers through
  `MeasureSpec::parse` in `ir_lower`, and round-trips with SPICE `.meas`
  imports. Spec body reuses the SPICE clause syntax so both source forms
  produce identical typed `MeasureExpr` values.
- [ ] **`four { ... }`** if A2 `.four` lands.
- [ ] **`fft { ... }`** if A2 `.fft` lands.

### B4. Embedded-language blocks (the `code "X" { ... }` mechanism)

Cirq's design for control flow is **not** to invent native Cirq control
syntax. Instead it has the generic embedded-language block:

```
code "control" {
    ... statements in the named language ...
}
```

(Defined in `cirq-grammar/grammar.js:207` as `code_decl`; stored in IR as
`Circuit::code_blocks: Vec<CodeBlock>` at `cirq-ir/src/lib.rs:42`.)

The point is extensibility: the same mechanism can later host an embedded
JS engine, a Python block, a domain-specific DSL, whatever — without
adding new Cirq syntax each time.

- [x] `code "control" { ... }` parses and lowers to a `CodeBlock`.
- [x] `control` language is handled by `thevenin-control`'s typed
  AST (let, echo, if/else, foreach, set, alter, print, run, stop when,
  resume, quit; recent typed control-AST commit 7ce12c3).
- [ ] **Configurable language registry.** Today the set of accepted
  language tags is implicitly fixed to whatever `thevenin-control` knows.
  Make this a real registry: a host application can register
  `("control", handler_fn)`, `("js", handler_fn)`, etc., and the parser
  / IR accept any registered tag and reject unknown ones with a clear
  diagnostic. Concretely: add a `LanguageRegistry` to `cirq-frontend`
  and route `CodeBlock` execution through it.
- [ ] **`while`, `repeat`** statements in the `control` language
  (matching A4).
- [ ] Document the registry interface and the contract a language
  handler must satisfy (input: block body string + circuit + sim
  context; output: side effects on sim context).

### B5. Modules, parameters, hierarchy

- [x] Module definitions with typed ports, positional + named
  instantiation, parameter overrides at call site, inline modules,
  nested modules.
- [x] Imports with relative paths, deduplication, circular detection.
- [x] `.global` keyword for shared nets.
- [ ] **Pin-by-name** connection syntax — `inst: m1(d: n1, g: n2, s:
  gnd, b: gnd)` may already work via named args; verify and
  document.
- [ ] **Port arrays / variable-width ports** beyond what `coupled_line`
  and `xspice` already do — needed if any custom multiport modules
  show up.

### B6. Comments and lexical

- [x] `//` line, `/* */` block.
- [ ] **Decision:** does Cirq accept `*` and `;` SPICE comments at all?
  Today only `//`. If we expect users to paste SPICE snippets into
  Cirq source occasionally, accepting `*` at start-of-line is cheap.
  *Lean: no — that's what the importer is for.*

### B7. Spec hygiene

- [ ] Audit `docs/cirq-spec/` for sections that still say "draft" or
  "future". Anything that isn't implemented in `ir_lower` should be
  marked clearly with `Status: planned` or removed.
- [ ] Bump `00-overview.md` from "0.2.0-draft / Implementation in
  progress" to a stable version string at release.

## Goal C — Cirq SPICE importer accepts arbitrary SPICE

### C1. Element coverage

- [x] R, L, C, V, I, E, F, G, H, B, D, Q, M, J, Z, K, O, Y, P, A, X
- [x] **S, W** (switches) — voltage-controlled `S` and current-controlled
  `W` elements parse via `thevenin-types`, map into IR through
  `cirq-spice-import`, and stamp via `thevenin/src/switch.rs`.
- [x] **U** (URC) — parsed via `thevenin-types` `'U'` branch and
  expanded at SPICE import time into R/C/D stages by
  `cirq-spice-import::expand_urc_in_netlist`.
- [x] **T** (ideal lossless line) — separate from O/Y; some netlists
  use it. Parsed in `thevenin-types/src/parse.rs` (`'T'` branch),
  lowered through `cirq-spice-import` → `IrElementKind::Tline`, stamped
  via `thevenin/src/tline.rs` (DC = wire, transient = method of
  characteristics with `VecDeque` history, AC = closed-form ABCD).
- [ ] **MOSFET level dispatch in importer** is detected via model kind
  alone; verify against BSIMSOI variants and VBIC `mtype`.

### C2. Model parsing

- [x] `.model NAME TYPE (k=v ...)` with `+` continuation, comments,
  case-insensitive keys.
- [x] Model binning (`foo.1`, `foo.2`) via synthetic aliases.
- [x] DeviceType::Other preserves verbatim kind strings for unknown
  models so simulator dispatch works.
- [ ] **Backslash line continuation** (rare, but real HSPICE files
  use it).
- [ ] **`.modeldir`** search-path directive — low priority but cheap.
- [ ] **Model parameter expressions** — `.model foo nmos (vto = {vt0+dvt})`
  with brace expressions referencing top-level params. Confirm this
  resolves end-to-end at import.

### C3. Directives

- [x] `.subckt`/`.ends` (nested), `.ic`, `.nodeset`, `.temp`, `.options`,
  `.param`, `.global`, `.save`, `.func`, `.include`, `.lib`, `.endl`,
  `.if/.elseif/.else/.endif`, `.title`, `.end`, `.control/.endc`,
  `.meas`, plus all analysis directives.
- [x] `.print` / `.probe` preserved as raw directives (output executes
  through the simulator's text output).
- [~] **`.step`** (PSPICE-style parametric sweep) — parsed with a stderr
  warning; execution deferred. Use a `.control` `foreach`/`while` loop
  for parametric sweeps in 1.0.
- [?] **`.alter` / `.alterparam`** (HSPICE) — parametric sweep variant.
  *Decision needed; lean: in scope as a diagnostic-with-workaround if
  not full support.*
- [x] **`.csparam`** (ngspice) — parsed; seeded into the `.control`
  variable scope via `SimContext::from_circuit`. `.param` deliberately
  is not seeded (ngspice behaviour).
- [x] **`.width`** — output formatting; recognised and silently passed
  through.

### C4. Expressions and brace evaluator

- [x] `+ - * / **`, function calls including int/floor/ceil/asin/
  acos/atan, log/ln/log10/exp, sqrt/abs/pow/min/max/sin/cos/tan, SI
  suffix parsing, multi-pass parameter resolution.
- [x] **Ternary `?:`** inside brace expressions — implemented in the
  importer's `eval_brace_expr` (cirq-spice-import) at lowest precedence
  with right-associativity; comparison operators (`> < >= <= == !=`)
  feed the condition. Resolver fallback in
  `thevenin::expr::resolve_netlist_exprs` remains for any path that
  bypasses the importer.
- [x] **`TEMPER` reference inside brace expressions** — importer seeds
  `TEMPER` from `.options temp=…` (defaulting to 27 degC) into the
  parameter resolution table before brace evaluation; identifier
  lookup falls back to case-insensitive matching so `TEMPER`, `temper`,
  `Temper` all resolve consistently.
- [ ] **`v(n1,n2)` / `i(vname)` references in non-B-element brace
  expressions** — these are valid SPICE in some contexts (e.g.
  `.print`, `.meas`). Currently behavioural-source only.
- [ ] **`if(c, t, e)`** function form in brace expressions.

### C5. `.include` / `.lib` actual file I/O

This is a real gap. Today the importer recognises the directives but
defers actual file resolution to the simulator side (or expects flattened
input).

- [x] **Importer-side `.include` resolver** — read referenced files
  relative to the source path, splice their contents in before
  parsing continues.
- [x] **Importer-side `.lib name`** — open the file, find
  `.lib name` ... `.endl name`, splice just that block.
- [x] **Search path control** — at minimum, the directory of the input
  file plus an explicit `--lib-path` CLI flag.

## Decisions log

All resolved 2026-05-23:

1. BSIM1 + BSIM2 → **in**.
2. HiSIM / HiSIMHV → **in**.
3. VDMOS → **in**.
4. `.four` / `.fft` → **in**.
5. `.disto` → **deferred post-1.0**. Touches every nonlinear device
   model; defer rather than block the release.
6. AC-mode `.sens` → **in**.
7. HSPICE / PSPICE dialect coverage → **out**. Anything beyond what stock
   ngspice itself parses is post-1.0.
8. Native Cirq control syntax → **no separate `control { ... }` block**.
   Reuse the existing `code "control" { ... }` embedded-language
   mechanism (keyword stays `code`), and make the language registry
   configurable so third parties can register additional language
   handlers (JS, Python, custom DSLs).
9. Switches (S, W) → **in**.
10. URC + other "weird MOSFET" variants (HICUM2, NUMOS, etc.) → **in** by
    extension. Needs an explicit enumeration pass against
    `ngspice-upstream/src/spicelib/devices/` before sizing the work.
